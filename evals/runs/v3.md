## Notes on the 5 failures
Four are C8 (per-commit skip justification / hedging, rule 4). SKILL.md rule 4 says a skip gets no entry at all, or at most one aggregate line listing skipped commit numbers — never per-commit justification. This run used the isolated single-commit-call harness (one API call per case), so "no entry" isn't really achievable per file; most skip cases correctly stayed to a bare `Skipped: commit N.` line, but four didn't:
- **Case 10** (ec87a17): added a reason clause ("documentation and wording cleanup with no user-visible change to the book recommender") instead of a bare skip.
- **Case 11** (1ac826a): same — added a reason clause in parentheses.
- **Case 18** (b50af03): added a reason clause *and* asked to reconsider ("If that file is actually the live already-read list... tell me and I'll write the entry"), which is a clearer, second violation of criterion 8 (asking/reconsidering).
- **Case 20** (f244f58): framed as an aggregate line ("Skipped commits: 20.") but still attached a reason clause ("the change has no effect visible to a user of the book-recommendation skill") — the aggregate-line exception in rule 4 is for a bare list of numbers, not a number plus a reason, so this doesn't actually qualify for it despite the framing.

One is C3 (skip-rule correctness):
- **Case 6** (1e3c29b): wrote a release note for a fix to the skill's own "what it does" description — internal/developer-facing, never seen by a user of the recommender. Every other reliable run (5, 7, 8, 9) correctly skips this commit.

This matches the known isolated-call format gap already logged in `decisions.md`'s 2026-09-15 "Rule 10... still gapped in isolated single-commit calls" entry — not a new failure mode, but a fresh data point for it.

## Why criterion 8's "per-commit justification" half is hand-graded, not scripted
The mechanical script can reliably catch a commit that explicitly asks for clarification, but not one that silently adds a reason clause to a skip without asking (cases 10, 11, 20 above) — case 20's wording ("Skipped commits: 20.") looks aggregate-shaped exactly like the rule's own permitted exception, and telling it apart from an actual violation requires reading whether the attached reason counts as justification, not pattern-matching.
