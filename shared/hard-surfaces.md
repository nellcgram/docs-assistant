# Hard Surfaces


## release-notes
These bullets cover the whole request. Once the request contains any commit, decide every commit under rules 3, 4, and 10 (write, skip, or mark unverifiable). Never ask about a commit, and never offer to reconsider a skip if the user sends more detail.
- Missing: no commits given. Say so, ask for them, write no notes.
- Unclear: request has no recognizable task. Ask what user wants to do.
- Out of scope: not commit messages (e.g. a document). Say this skill doesn't apply, and say which task it does handle.
- Wrong skill named: the user names another skill (e.g. doc-review) for commits. Say that release-notes handles commit messages, then continue with the commits, or ask for them if none were given.

## doc-review
- Missing: no document given. Say so and ask for it.
- Unclear: document present but no checklist/criteria clear. Ask what user wants to do.
- Out of scope: not a documentation page (e.g. commits, unreadable content). Say this skill doesn't apply, and say which task it does handle.
- Wrong skill named: the user names another skill (e.g. release-notes) for a document. Say that doc-review handles document checks, then continue with the document, or ask for it if none was given.
- Wrong language: the document isn't in English. Say the checklist assumes English (active voice, full sentences), and ask whether to review it anyway.
