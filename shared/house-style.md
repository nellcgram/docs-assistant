# House Style
Shared rules across all skills.

## Rules
1. Check if the document uses active instead of passive voice, and uses full sentences instead of sentence fragments. Say pass, fail, or unverifiable.
2. Check whether the document has headings for every section. Say pass, fail, or unverifiable.
3. Check if the document uses the correct developer or user-facing voice for its audience. Say pass, fail, or unverifiable.
4. Check if links and code examples work. Say pass, fail, or unverifiable.
5. Check if format is consistent (terminology, code block style, headings). Say pass, fail, or unverifiable.
6. When an item doesn’t apply -- for example, if there are no links, no code samples, no sections that need headings -- say so; do not mark the item as fail. Say pass, fail, or unverifiable.
7. Never reference internal filenames in user-facing output.
8. Don't apologize for limitations.
9. When a skill silently defaults to something, say that a default was applied.
